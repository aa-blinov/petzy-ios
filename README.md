# Petzy для iOS

Нативное приложение дневника здоровья питомца на SwiftUI. Работает с тем же
API, что и веб-приложение: аккаунт, питомцы, записи и остальное живут в одном
месте.

Бэкенд лежит в отдельном репозитории (`petzy`, Flask + MongoDB). Этот
репозиторий только про приложение.

## Что уже работает

- Вход по логину и паролю, токены в Keychain
- Автоматическое обновление истёкшего токена и повтор запроса
- Список питомцев с видом, породой и датой рождения
- Выход с устройства

## Разработка по TDD

Проект пишется через тесты: сначала падающий, потом код, потом уборка. Сеть в
юнит-тестах настоящей не бывает, `StubURLProtocol` отвечает заготовками.
Подробности, включая проверку того, что тест упал по нужной причине, в
`AGENTS.md`.

```bash
make test     # юнит-тесты, быстро, без сервера
make test-ui  # прогон экранов против живого локального стека
```

## Начало

Нужен Xcode и Homebrew.

```bash
make setup
```

Эта команда поставит `xcodegen` и `swiftlint`, если их нет, и соберёт
`Petzy.xcodeproj`. Сам файл проекта в git не хранится: он генерируется из
`project.yml`, и правится именно `project.yml`.

Поднимите локальный стек petzy, чтобы было куда ходить:

```bash
make backend
```

Затем запустите приложение:

```bash
make run
```

Вход в локальный стек: `demo` / `petzy-demo-2026`.

## Команды

| Команда | Что делает |
|---|---|
| `make setup` | Ставит xcodegen и swiftlint, генерирует проект |
| `make generate` | Пересобирает `Petzy.xcodeproj` из `project.yml` |
| `make open` | Открывает проект в Xcode |
| `make build` | Собирает под симулятор |
| `make test` | Прогоняет юнит-тесты |
| `make test-ui` | Прогоняет UI-тесты против локального стека |
| `make run` | Собирает, ставит и запускает на симуляторе |
| `make shot` | Скриншот текущего экрана |
| `make lint` | Проверка стиля |
| `make format` | Приводит код к виду по `.swiftformat` |
| `make hooks` | Включает гит-хуки, один раз на клон |
| `make backend` | Поднимает локальный стек petzy в Docker |
| `make backend-stop` | Останавливает его |
| `make clean` | Убирает сборку и сгенерированный проект |

`make help` покажет то же списком.

Другой симулятор: `make run SIM="iPhone 17 Pro"`.

## Другой сервер

По умолчанию приложение ходит на локальный стек petzy (`http://localhost:5002`).
Адрес лежит в `PETZY_API_BASE_URL` в `project.yml` и попадает в `Info.plist`.
Чтобы разово уйти на другой сервер, не меняя файл, передайте аргумент при
запуске:

```bash
xcrun simctl launch booted ru.petzy.app -petzyBaseURL https://petzy.duckdns.org
```

Симулятор видит Mac по `localhost`. Настоящий телефон так не достучится до
`localhost`: ему нужен адрес Mac в локальной сети, и для него придётся
ослабить `NSAllowsLocalNetworking` в `Info.plist`. Не сделано: подписи пока
нет, на устройство собирать нечем.

## Симулятор в Xcode 27

Отдельного `Simulator.app` больше нет, окно симулятора это `DeviceHub.app`
внутри Xcode. `make run` открывает его сам, с нужным устройством. Без этого
приложение запускается, но снимки экрана выходят совершенно чёрными: дисплей
не подключён. Проверить просто, снимок домашнего экрана тоже чёрный.

Софтверная клавиатура в этом окружении рисуется неполностью, три клавиши
вместо тридцати, и буквы в неё не попадают. Поэтому UI-тесты не набирают пароль,
а получают его через переменные окружения запуска. Само нажатие «Войти»
остаётся настоящим, весь путь проверяется. Подробности в `AGENTS.md`.
